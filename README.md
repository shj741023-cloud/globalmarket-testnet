# Global Market Testnet

Pi Testnet과 Test-Pi만 사용하는 기능검증용 MVP입니다. Mainnet과 실제 판매자 지급은 코드에서 허용하지 않습니다.

## 실행

Node.js 22 이상에서:

```text
npm start
```

브라우저에서 `http://localhost:3000`을 엽니다. 외부 패키지 설치가 필요하지 않습니다.

## 테스트

```text
npm test
```

## Pi Sandbox 연결

`.env.example`을 참고해 실행환경에 `PI_API_KEY`를 설정할 수 있습니다. 이 프로토타입은 `.env` 파일을 자동으로 읽지 않으므로 운영체제 환경변수로 주입해야 합니다. 키가 없으면 서버 승인·완료 단계가 명시적인 모의 응답으로 처리됩니다.

Pi 로그인 시 프런트엔드가 받은 액세스토큰을 서버의 `/api/v1/auth/pi`로 전달하며, 서버는 Pi `/v2/me` 응답으로 사용자를 검증한 뒤 HttpOnly 세션 쿠키를 발급합니다. 클라이언트가 보낸 사용자 ID는 신뢰하지 않습니다.

로컬 데모 인증은 기본적으로 꺼져 있습니다. 필요한 경우에만 `ALLOW_DEMO_AUTH=true`로 설정하고 `/api/v1/auth/demo`를 사용합니다.

판매자는 `/api/v1/me/products`에서 자신의 상품 전체를 확인하고, 상품 수정 및 판매중지·재개를 할 수 있습니다. 다른 판매자의 상품, 진행 중 거래가 있는 상품, 검토·예약·판매완료 상태는 서버에서 보호합니다.

거래 상세·배송정보·결제 승인과 완료는 로그인한 거래 당사자에게만 허용됩니다. 배송완료 시뮬레이션, 자동 구매확정, 모의정산 같은 내부 Testnet 작업은 `TEST_ADMIN_KEY`가 있어야 실행됩니다.

`/api/v1/me/trades`에서 구매·판매 역할, 거래상태, 직거래·택배 방식을 조합해 내 거래를 조회할 수 있습니다. 거래 상세에는 상품, Test-Pi 결제, 배송, 직거래 약속, 분쟁, 환불, 모의정산, 후기 진행정보가 함께 제공됩니다.

사용자 화면에는 상품 복합검색, 상품등록·수정·판매중지, 내 채팅과 양쪽 거래합의, 내 거래의 상태별 다음 작업, 알림·신뢰등급·신고·후기·로그아웃이 연결되어 있습니다. 직거래 화면에는 플랫폼 안전거래가 없다는 본인책임 확인이 필수이며, Testnet 택배 화면만 Test-Pi 결제·배송·구매확정·분쟁 흐름을 제공합니다.

Render 배포 시 `render.yaml`을 사용할 수 있습니다. `PI_API_KEY`와 `TEST_ADMIN_KEY`는 저장소 파일에 쓰지 말고 Render의 Secret 환경변수로 입력합니다. `public/validation-key.txt`는 Pi Developer Portal 도메인 확인을 위해 공개되는 파일입니다. 무료 Render 파일시스템은 재시작 시 초기화되므로 기능검증용으로만 사용합니다.

Pi Developer Portal의 Transaction on the App 확인에는 로그인 후 표시되는 `0.01 Test-Pi 연동시험` 버튼을 사용합니다. 이 거래는 Testnet 체크리스트 검증 전용이며 실제 상품거래·실제 Pi·판매자 정산과 분리됩니다.

결제 상태는 별도 모듈에서 관리하며 거래당 활성 결제 1개, Pi 결제 ID와 트랜잭션 ID 중복 차단, 승인 전 완료 금지, 반복 완료의 멱등 처리, 본인 미완료 결제 조회를 적용합니다.

## 안전 기준

- `APP_NETWORK=testnet`
- `PI_SANDBOX=true`
- Test-Pi만 사용
- 직거래 결제·정산·환불 API 차단
- 판매자 정산은 내부 모의 원장만 기록
- 외부 판매자 지갑 송금 없음
- 실제 개인정보와 실제 상품대금 사용 금지

## 구현된 거래 흐름

- 판매자 배송 등록
- 배송완료와 3일 후 자동 구매확정 예정시각
- 구매자의 직접 구매확정
- 기한 도달 거래의 자동 구매확정 작업
- 분쟁 접수 즉시 구매확정·정산 보류
- 구매확정 후 외부 송금 없는 모의 정산
- 전액 환불 시 구매자 모의 수수료 반환과 판매자 수수료 미부과
- 부분 환불 시 보유 거래금액 기준 양쪽 수수료 재계산
- 관리자 Testnet 분쟁판정과 모의환불

관리자 분쟁판정 API는 `TEST_ADMIN_KEY`가 설정된 경우에만 활성화되며 요청의 `x-test-admin-key` 값이 일치해야 합니다.

## 후기와 신뢰

- 신규 사용자 50점
- 정상 거래완료 +2, 긍정 후기 +1, 구매확정 +1
- 신고 접수만으로 감점하지 않음
- 확정 위반만 -3~-20 적용
- 동일 사건 중복 반영 방지
- Bronze, Silver, Gold, Platinum, Diamond 등급 계산

## 상품 범위와 검색

- 국내 개인 간 실물 중고상품 카테고리만 제공
- 상품명·설명·가격·카테고리·거래방식 검증
- 금지·제한 품목 의심 시 공개하지 않고 검토중 처리
- 의심어만으로 사용자를 자동 제재하지 않음
- 검색어·카테고리·지역·가격·거래방식 필터

## 채팅과 거래합의

- 상품·구매자·판매자별 활성 채팅방 1개
- 채팅 당사자만 메시지·가격제안·합의 접근
- 가격제안 수락·거절은 상대방만 가능
- 가격과 거래방식을 양쪽이 확인해야 거래 생성
- 조건 변경 시 기존 양쪽 확인 자동 해제
- 같은 합의로 거래 중복 생성 방지
- 직접 거래생성 임시 API는 기본 차단

## 신고·관리자 운영

- 사용자 신고 접수와 처리현황 조회
- 신고 접수만으로 신뢰점수 변경 없음
- 접수 24시간, 1차 검토 3영업일, 일반 7영업일, 복잡 14영업일 목표
- 관리자 담당자 배정 후 사유가 있는 판정
- 관리자 중요 작업의 변경 전후 감사로그
- 신고·분쟁 접수와 판정 결과 알림

## 직거래

- 본인 책임 안내 확인 후 약속 생성
- 시간·장소·당사자 간 결제방법 기록
- 거래 당사자만 약속 변경·완료·취소 가능
- 양쪽 완료 표시 후 거래완료와 후기 활성화
- 플랫폼 결제·대금보관·정산·환불 데이터 생성 금지
